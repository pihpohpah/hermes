# Архитектурный стандарт фронтенда (Hypermedia-First + Alpine.js + Rare React Islands)

Этот скилл объединяет лучшие практики из [Mindrally (`htmx`, `alpine-js`)](https://github.com/mindrally/skills) и [Vercel Engineering (`vercel-react-best-practices`)](https://github.com/vercel-labs/agent-skills) в единую прагматичную архитектуру.

---

## 1. Базовая философия и иерархия выбора технологий

Главный принцип фронтенда — **радикальная простота и отсутствие лишнего клиентского JS**.

Выбор инструмента всегда идет строго по лестнице эскалации (от простого к сложному):

1. **Уровень 1 — Hypermedia (HTMX) и чистый REST (Основа приложения — 80% задач)**:
   - Сервер является единственным источником правды для бизнес-состояния и шаблонов.
   - Для UI-взаимодействий (таблицы, фильтрация, пагинация, отправка форм, CRUD) сервер отдает готовые HTML-фрагменты через HTMX (`hx-get`, `hx-post`, `hx-put`, `hx-patch`, `hx-delete`, `hx-target`, `hx-swap`), либо чистые REST JSON-ответы (`{"success": bool, "error": string, "data": ...}`) для внешних API и легких виджетов.
2. **Уровень 2 — Alpine.js (Основа транзишенов и локального UI-состояния — 18% задач)**:
   - Все клиентские переходы и анимации (`x-transition`), модалки, дропдауны, тултипы, табы, переключение видимости (`x-show`) и легкая валидация полей до отправки (`x-model`) реализуются **только на Alpine.js** в связке с утилитарным CSS (Tailwind CSS).
   - Alpine дополняет HTMX, управляя состоянием, которое не требует похода на сервер, или красиво анимируя появление/скрытие блоков.
3. **Уровень 3 — React-острова (Крайне редкие кейсы — < 2% задач)**:
   - React **запрещено** тащить для обычных страниц, форм, таблиц, каталогов или дашбордов.
   - React допускается **только** как изолированный «остров» (Island) для высокоинтерактивных rich-client задач: сложный canvas/node-редактор, real-time графики с тысячами точек, тяжелый многошаговый конфигуратор с мгновенным клиентским пересчетом графа зависимостей.
   - Если React используется, он обязан строго следовать правилам производительности **Vercel React Best Practices** (отсутствие водопадов запросов, прямые импорты без barrel-файлов, минимизация ре-рендеров).

## 2. Общие правила написания фронтенд-кода

1. **Минимум комментариев**:
   - Не комментируй стандартные атрибуты `hx-*` или директивы `x-*`.
   - Разметка должна читаться декларативно за счет семантичных HTML-тегов и понятных имен в `x-data`.
   - Оставляй комментарии только для неочевидных контрактов с бэкендом (например, какие кастомные заголовки `HX-Trigger` ожидает компонент).
2. **Декларативность вместо императивного JS**:
   - Не пиши `document.querySelector` и ручные `addEventListener`, если задачу решают `hx-trigger` или `@click` / `@keydown.escape.window` в Alpine.
   - Выноси повторяющиеся объекты состояния в `Alpine.data('name', () => ({ ... }))`, чтобы не раздувать инлайновые атрибуты `x-data` в HTML.
3. **Единый дизайн переходов (Transitions)**:
   - Любое появление/скрытие выпадающих меню, модальных окон, тостов и панелей фильтров оформляется через `x-show` + `x-transition` (с модификаторами `enter`, `leave`, `duration`, `scale`, `opacity`).
4. **Чистая интеграция с Go-бэкендом**:
   - Страницы и HTMX-партиалы рендерятся на сервере (`html/template` или `templ`) либо запрашивают стандартный REST-контракт `/api/v1/...` (обертка `APIResponse[T]`: `{"success": true, "error": "", "data": ...}`).

## 4. Чек-лист принятия архитектурного решения (Decision Tree)

Перед созданием любого UI-элемента пройди по списку сверху вниз:
1. **Нужно загрузить, отфильтровать, создать, изменить или удалить данные на сервере?**
   -> Используй **HTMX** (`hx-get`, `hx-post`, `hx-delete`, `hx-target`, `hx-swap`) и верни с сервера минимальный HTML-фрагмент (или вызови REST-ручку `/api/v1/...` из маленького `Alpine.data` компонента, если бэкенд отдает только JSON).
2. **Нужно плавно открыть/закрыть элемент, переключить таб, показать спиннер или провалидировать инпут на лету?**
   -> Используй **Alpine.js** (`x-data`, `x-show`, `x-transition`, `x-bind:class`).
3. **Кажется, что нужен React?**
   -> Проверь, нельзя ли решить задачу комбинацией `hx-get` + `Alpine.data()`. Подключай React-остров **только** если состояние полностью живет на клиенте (сложный drag-and-drop граф, canvas, высокочастотный стриминг) и соблюдай правила из [react-islands-best-practices.md](<references/react-islands-best-practices.md>).
