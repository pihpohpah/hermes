# Офлайн-карта Приморского края

Векторная карта региона собирается один раз в PMTiles-архив и раздаётся
бекендом байтовыми диапазонами. В git архив **не попадает** (десятки MB):
файл лежит на диске сервера, локально собирается командой.

Документ описывает, как карта устроена в приложении (стиль, режимы, офлайн),
и пайплайн сборки архивов.

## Компоненты

| Компонент | Назначение |
| --- | --- |
| `scripts/map/build-map.sh`, `config.json`, `process.lua` | Сборка векторного архива из OSM |
| `scripts/map/build-relief.sh` | Сборка архива рельефа из Copernicus DEM |
| `web/static/pmtiles/*.pmtiles` | Артефакты сборки, в git не коммитятся |
| `internal/application/routes/http/pmtiles.go` | Отдача архивов с `Range` и `ETag` |
| `internal/application/routes/http/map_page.go` | Стиль (вырезает рельеф, если архива нет), ассеты `/map/*` без листинга каталогов |
| `web/map/style.json` | Стиль подложки: слои, режимы, ссылки на токены |
| `web/map/vendor/`, `web/map/fonts/` | MapLibre GL JS 5.24.1, PMTiles 4.5.0, глифы Noto Sans — карта не зависит от CDN |
| `web/static/js/app/map.js` | Контроллер карты приложения: маркеры, кластеры, маршрут, мини-карты |
| `web/static/js/app/map-style.js` | Загрузка стиля, подстановка токенов, режимы слоёв |
| `web/static/js/app/map-tiles.js` | Протокол `pmtiles://`, кеш кусков, скачанная копия |
| `web/static/js/app/offline-map.js` | Блок «Офлайн-карта» в профиле |
| `cmd/mapserver` (+ вшитая `dev.html`) | Отладка стиля без Postgres |

Карта используется на «Карте», в «Сейчас», в мини-карте страницы места и при
выборе точки в мастере добавления — везде через `createPlacesMap` или
`createBaseMap` из `map.js`, поэтому подложка, стиль и офлайн у них общие.

## Стиль и токены

Цвета в `web/map/style.json` записаны ссылками на CSS-токены:
`"fill-color": "var(--map-park)"`. Значения токенов живут в
`web/static/css/app.css` (блок «Карта» в `:root`), `map-style.js` подставляет
их перед созданием карты. Поэтому карта и интерфейс меняются из одного места,
а новый цвет в стиле — это новый токен `--map-*` в `app.css`; неизвестный токен
выводит предупреждение в консоль и рисуется чёрным.

Стиль без клиента не самодостаточен: MapLibre, открытый напрямую на
`style.json`, ссылки `var(...)` не поймёт. Смотреть и править стиль удобно на
отладочной странице `mise run map-serve` → `/map/`: она рисует карту тем же
модулем, что и приложение, и подхватывает правки `style.json` и `app.css` по F5
без сборки.

Что можно настроить:

- **Цвета и толщины** — в `paint` слоя (`line-width`, `fill-color`) или в токене.
  Ширины дорог интерполируются экспоненциально до z18: архив заканчивается на
  z15, дальше MapLibre масштабирует тайлы сам.
- **Видимость по зуму** — `minzoom`/`maxzoom` слоя. Данных выше зума архива не
  появится, сколько бы ни поставить `minzoom`.
- **Порядок отрисовки** — порядок в массиве `layers`: последний рисуется сверху.
  Обводки дорог (`*-casing`) стоят под всеми заливками, иначе рвутся перекрёстки.
- **Фильтры** — по атрибутам тайлов (`class`, `subclass`, `hiking_route`,
  `admin_level`). Полный список атрибутов — в метаданных архива:
  ```bash
  docker run --rm -v "$PWD/web/static/pmtiles:/out" ghcr.io/protomaps/go-pmtiles:latest \
    show /out/primorsky-krai-z15.pmtiles --metadata
  ```
- **Подписи** — `text-field`, `text-font`, `text-size`, `text-halo-*`. Шрифты
  ограничены теми, что лежат в `web/map/fonts/`: `Noto Sans Regular`, `Bold`,
  `Italic`, только латиница и кириллица.

Решения, унаследованные от дизайна (`vlru-places/docs/map.md`): POI-подписи
выключены — смысловые точки ставит только продукт; границы рисуются только
крупные (`admin_level <= 4`) — муниципальные идут по берегу и сливаются с ним
в пунктир. Морские участки границ отбрасываются ещё при сборке тайлов.

## Режимы «Город» и «Природа»

Режим слоя задан в `metadata["hermes:mode"]`: `city`, `nature` или `both`
(слой без метки — `city`). Сценарий «Природа» включает режим `nature`:
растровый рельеф (`relief-zones`) с водой, тропами, вершинами и подписями;
«Город», «Море» и «Сейчас» — режим `city`. Режим выбирается до создания карты,
поэтому лишние слои не мелькают.

Рельеф плоский: объём даёт отмывка, запечённая в растр при сборке (цвет зоны ×
hillshade), а не 3D-terrain — один PNG на тайл грузится быстро, наклон камеры
не мешает маркерам и панелям. Яркость и насыщенность растра подстраиваются
полями `raster-*` слоя без пересборки. DEM-архив (`primorsky-dem.pmtiles`)
скрипт по-прежнему собирает, но приложение его не использует.

Диапазон зумов рельефа берётся из заголовка архива, а не из стиля: локальная
сборка (`map-relief-local`) покрывает z10–13, полная — z3–13. Ниже покрытия
под рельефом виден фон `--map-nature-land` (цвет суши) с водой и подписями.
Если архива рельефа на сервере нет, `MapStyleHandler` вырезает источник и его
слои, а «Природа» показывает городскую подложку. Наличие архива проверяется на
каждый запрос стиля — после сборки перезапускать сервер не нужно.

## Офлайн

Порядок источников для каждого куска архива (`map-tiles.js`):

1. **Сервер** — HTTP `Range`. Основной путь, всегда первый.
2. **Скачанная копия** — если сеть или сервер недоступны и копия есть.
3. **Кеш кусков** — всё, что карта уже получала онлайн.

| Что | Где | Размер |
| --- | --- | --- |
| Просмотренные куски архивов | IndexedDB `hermes-map`, стор `chunks` | ~150 КБ на экран |
| Скачанные архивы целиком | IndexedDB `hermes-map`, стор `archives` | ~95 МБ карта + рельеф |

**Кеш кусков.** Ответы `206 Partial Content` браузеры кешируют ненадёжно,
поэтому каждый полученный диапазон складывается в IndexedDB пачками раз в
300 мс. После этого уже просмотренные области открываются без сервера.

**Скачанная копия.** Блок «Офлайн-карта» в профиле (только после входа)
скачивает все собранные архивы целиком, показывает прогресс, размер и дату,
умеет отменять, удалять копию и очищать кеш кусков. Копия хранится на
устройстве и к аккаунту не привязана. После скачивания запрашивается
`navigator.storage.persist()`, чтобы браузер не вытеснил данные.

**Версии.** `PMTilesHandler` отдаёт сильный `ETag` из размера и mtime файла
(`http.ServeFile` его сам не ставит). Куски кешируются с ключом
`<архив>|<ETag>|<смещение>:<длина>`; пришёл кусок с новым ETag — старые куски
этого архива удаляются. Копия хранит свой ETag, и офлайн-сессия, начатая с
копии, читает только её версию: смещения старого и нового архива указывают в
разные байты, смешивать их нельзя. Профиль сравнивает ETag копии с сервером и
предлагает «Обновить», когда архив пересобран.

## Логика hiking-отношений в `process.lua`

В профиле есть обработка отношений `route=hiking`: `relation_scan_function`
принимает такие отношения, `way_function` помечает их участки атрибутом
`hiking_route=1` и опускает их до z12. На момент
сборки (ноябрь 2026) в экстракте Приморского края таких отношений **нет** —
есть только `bus`, `road`, `train`, `ferry`. Поэтому фактически тропы
определяются по тегу `highway` (`path`, `bridleway`), а код для отношений
пока не срабатывает. Он оставлен как задел и заработает, когда отношения
появятся в OSM; до этого его можно считать непроверенным в бою.

## Что покрыто

| Параметр | Значение |
| --- | --- |
| Границы | административная граница Приморского края (OSM relation `151225`, ISO `RU-PRI`) |
| Extent | `130.39, 42.12 – 139.31, 48.47` |
| Zoom | `0–15` (детализация до отдельных зданий и троп) |
| Размер архива | ~96 MB (`z15`, ~427 тыс. тайлов) |
| Формат | MVT (protobuf) внутри PMTiles v3, gzip |
| Слои | `water`, `waterway`, `transportation`, `transportation_name`, `building`, `landuse`, `landcover`, `park`, `poi`, `place`, `boundary`, `mountain_peak`, `aeroway`, `housenumber` |

В покрытие входят Владивосток (агломерация, о. Русский, бухта Петра Великого),
Находка, Уссурийск, побережье Японского моря и частично Сихотэ-Алинь.

Обрезка идёт по административной границе, а не по прямоугольнику: иначе в архив
попадают Китай, Хабаровский край и ЕАО. Пограничные тайлы могут захватывать
соседнюю территорию — это неизбежно при тайловой сетке, таких тайлов менее 2%.

## Быстрый старт

```bash
mise run bootstrap        # .env и зависимости Go
mise run map-download     # скачать OSM и собрать архив (~5–10 мин при первом запуске)
mise run map-serve        # отладочная карта на http://127.0.0.1:8080/map/
```

Проверка, что архив отдаётся диапазонами (а не целиком):

```bash
mise run map-check
curl -r 0-1023 http://localhost:8080/api/map/region.pmtiles | head -c 100 | xxd
```

Ожидаемый ответ — `206 Partial Content`, ровно 1024 байта и сигнатура `PMTiles`
в первых байтах.

## Как перегенерировать карту

Полная сборка одной командой:

```bash
mise run map-download
```

Скрипт `scripts/map/build-map.sh` выполняет шаги:

1. **Скачивание** — `far-eastern-fed-district-latest.osm.pbf` (~400 MB) с Geofabrik
   в `.cache/map/`. Файл кэшируется: повторный запуск его не качает.
2. **Граница края** — из экстракта достаётся relation `151225` («Приморский край»,
   `admin_level=4`) и конвертируется в GeoJSON.
3. **Кроп по границе** — `osmium extract --polygon boundary-r151225.geojson` →
   `primorsky.osm.pbf` (~49 MB).
4. **Береговая линия** — Water polygons с osmdata.openstreetmap.de обрезаются
   по той же границе края через GDAL (слой `ocean`). Кэшируется в
   `.cache/map/coastline/`.
5. **Рендер тайлов** — tilemaker с профилем `scripts/map/{config,process}.lua`.
6. **Конвертация** — MBTiles → PMTiles и проверка структуры (`pmtiles verify`).

Параметры переопределяются переменными окружения:

```bash
MAP_MAXZOOM=13 mise run map-download          # более грубая карта, меньше файл
MAP_OUTPUT=/srv/maps/region.pmtiles mise run map-download
MAP_KRAI_RELATION_ID=1647394 mise run map-download   # границы Владивостокского округа
```

Промежуточные файлы складываются в `.cache/map/` (в `.gitignore`), поэтому
повторная сборка после правки профиля занимает секунды.

## Состав пайплайна

```
scripts/map/
├── build-map.sh        # оркестратор: скачивание → граница → кроп → тайлы → PMTiles
├── config.json         # слои, zoom-диапазоны, метаданные архива
├── process.lua         # OpenMapTiles-профиль + правки под хайкинг
└── Dockerfile.tools    # образ tilemaker + osmium (собирается автоматически)
```

Нужен только **Docker**: образы `ghcr.io/systemed/tilemaker`, `ghcr.io/osgeo/gdal`,
`ghcr.io/protomaps/go-pmtiles` подтягиваются автоматически.

## Профиль тайлов

`process.lua` — профиль OpenMapTiles из tilemaker с правками:

- `highway=path` и `highway=bridleway` поднимаются с z14 до **z12**, чтобы тропы
  были видны при планировании маршрута, а не только на максимальном приближении
  (городские тротуары `footway`/`steps`/`pedestrian` остаются на z14: их
  миллионы, и подъём раздул бы архив без пользы для хайкинга);
- у таких линий появляется атрибут `hiking_route=1`.

Верхний зум детализации вынесен в константу `MAX_ZOOM` в самом профиле и должен
совпадать с `maxzoom`/`basezoom` в `config.json`. Профиль не читает конфиг, поэтому
при смене зума правятся оба места — `build-map.sh` подставляет `MAP_MAXZOOM`
в конфиг автоматически, но `process.lua` при нестандартном значении нужно
поправить руками.

## Эндпоинты

| Метод | Путь | Что |
| --- | --- | --- |
| `GET`/`HEAD` | `/api/map/region.pmtiles` | векторный архив, `Range` + `ETag` |
| `GET`/`HEAD` | `/api/map/relief.pmtiles` | архив рельефа, `Range` + `ETag` |
| `GET` | `/map/style.json` | стиль без источников несобранных архивов |
| `GET` | `/map/**` | MapLibre, PMTiles, глифы |
| `GET` | `/map/` | отладочная страница, только в `cmd/mapserver` |

Архивы отдаются с `Accept-Ranges: bytes` и `Cache-Control: public, max-age=3600`.
Если файла нет, эндпоинт отвечает `503`; карта в приложении показывает
«Карта не загрузилась».

## Разработка карты отдельно от бекенда

`cmd/mapserver` поднимает стиль, архивы, статику приложения и отладочную
страницу — без Postgres и остальных сервисов:

```bash
mise run map-serve          # http://127.0.0.1:8080/map/ (?s=nature — сразу «Природа»)
```

Флаги: `-addr :8080`, `-map-dir ./web/map`, `-web-dir ./web/static`,
`-archive ./web/static/pmtiles/primorsky-krai-z15.pmtiles`,
`-relief ./web/static/pmtiles/primorsky-relief.pmtiles`
(или переменные `MAP_ADDR`, `MAP_DIR`, `WEB_DIR`, `PMTILES_PATH`, `RELIEF_PATH`).

Страница грузит модули `web/static/js/app/` и `app.css` напрямую, без бандла,
поэтому правки JS, CSS и стиля видны по F5. В приложение JS попадает только
через `mise run assets`.

## Известные ограничения

- **Без сети не открывается сама страница.** Service Worker для оболочки
  приложения нет, поэтому офлайн-копия и кеш кусков помогают, когда страница
  уже открыта или недоступен только сервер карты. Полный офлайн требует
  precache оболочки — см. «Офлайн-стратегию» в README.
- **Кеш кусков неполный.** Без сети и без скачанной копии доступны только те
  области и зумы, которые реально запрашивались.
- **Кеш кусков не ограничен по размеру.** Он растёт по мере просмотра; очистить
  можно в профиле. Старая версия вытесняется автоматически при пересборке архива.
- **Скачивание не докачивается.** Обрыв или нехватка места — скачивание
  начинается заново; прежняя копия остаётся, пока новая не скачана целиком.
- **Скачивание держит архивы в памяти** до записи в IndexedDB (~95 МБ).

## Если архив больше 500 MB

Текущая сборка — ~96 MB, запас большой. Если после смены зума файл перевалит
за 500 MB, скрипт сам выведет предупреждение. Варианты:

1. **Снизить максимальный зум** — самый эффективный рычаг:
   ```bash
   MAP_MAXZOOM=13 mise run map-download
   ```
2. **Два архива (LOD-схема)** — z13 на весь край + z15 на агломерацию:
   ```bash
   MAP_MAXZOOM=13 MAP_OUTPUT=web/static/pmtiles/primorsky-z13.pmtiles mise run map-download
   MAP_MAXZOOM=15 MAP_OUTPUT=web/static/pmtiles/vladivostok-z15.pmtiles mise run map-download
   ```
   Для второго архива область задаётся OSM-отношением через `MAP_KRAI_RELATION_ID`
   (например, `1647394` — Владивостокский городской округ), а не прямоугольником.
   На фронте детальный архив подключается как дополнительный source и включается
   при `zoom >= 13`.
3. **zstd** — PMTiles уже хранит тайлы gzip-сжатыми, поэтому повторное сжатие
   архива даёт единицы процентов. Реальный выигрыш даёт только снижение зума
   или отказ от слоя `building` на больших зумах.

## Проверка результата

- **Range-запросы**: `mise run map-check` (ожидает `206` и 1024 байта).
- **Валидность архива**: `pmtiles verify` вызывается скриптом сборки автоматически;
  визуально архив открывается на <https://pmtiles.io/>.
- **Офлайн-режим**: на открытой карте в devtools заблокировать запросы
  `*.pmtiles` и подвигать карту — просмотренные области рисуются из кеша
  кусков, остальные — из скачанной в профиле копии.
- **Размер**: `mise run map-size` — должно быть меньше 500 MB.
