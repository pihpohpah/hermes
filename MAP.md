# Офлайн-карта Приморского края

Векторная карта региона собирается один раз в PMTiles-архив и раздаётся
бекендом байтовыми диапазонами. В git архив **не попадает** (десятки MB):
на хакатоне файл лежит на диске сервера, локально собирается командой.

Документ описывает пайплайн сборки архива (это постоянная часть) и отдельно —
то, что сделано **как временный демонстрационный вариант** и подлежит замене.

## Статус компонентов

| Компонент | Статус | Комментарий |
| --- | --- | --- |
| `scripts/map/build-map.sh`, `config.json`, `process.lua` | **постоянный** | Пайплайн сборки архива, переиспользуется как есть |
| `web/static/pmtiles/primorsky-krai-z15.pmtiles` | **постоянный** | Артефакт сборки, лежит на диске, в git не коммитится |
| `internal/application/routes/http/pmtiles.go` | **постоянный** | Отдача архива с поддержкой `Range` |
| `GET /api/map/region.pmtiles` | **постоянный** | Контракт эндпоинта |
| `internal/application/routes/http/map_page.go` + `/map/` | **демонстрационный** | Страница-витрина, не часть продуктового UI |
| `web/map/` (`index.html`, `style.json`, `vendor/`, `fonts/`) | **демонстрационный** | Отдельная статическая страница, не интегрирована в приложение |
| `cmd/mapserver` | **демонстрационный** | Отдельный dev-сервер, чтобы не поднимать Postgres |
| `GET /api/pmtiles/region.pmtiles` | **демонстрационный** | Алиас под старую заглушку в `web/static/index.html` |
| `web/map/offline.js` — кнопка «Скачать карту» | **демонстрационный** | Тестовая загрузка архива в IndexedDB |
| `web/map/sw.js` — precache оболочки | **демонстрационный** | Учебный SW, в проде заменяется на Workbox |

## Что именно является временным демонстрационным вариантом

Ниже — перечень того, что сделано «чтобы проверить, что карта работает», и что
планируется заменить. Это не продакшн-код.

### 1. Страница `web/map/index.html` и каталог `web/map/`

Это самостоятельная страница-витрина: открывается по `/map/`, рисует карту,
позволяет скроллить и зумить. Она **не является** частью продуктового фронтенда:

- в проекте пока нет приложения на React + Vite, куда монтируется карта —
  в `web/static/index.html` под неё оставлен только пустой остров
  `#react-map-island`;
- страница не использует дизайн-систему проекта (`design/`), у неё свой
  минимальный набор CSS прямо в файле;
- нет слоёв приложения: точек из PostGIS, карточек мест, фильтров, маркеров и
  кластеров — только подложка;
- нет интеграции с HTMX/Alpine-оболочкой приложения.

Когда появится реальный React-island, содержимое `web/map/` переедет в него:
источник тайлов, стиль и регистрация протокола PMTiles — переиспользуются,
страница и её CSS — нет.

### 2. Стиль `web/map/style.json`

Демонстрационный стиль, у которого ключевые цвета подобраны под токены дизайна
(`--color-map-water` `#dcecf0`, `--color-map-land` `#f3f0e7`,
`--color-map-green` `#dce9d9`) — но **значения вписаны в стиль как hex**, а не
взяты из `design/css/tokens.css` напрямую. При изменении токенов стиль
разъедется и его надо будет править руками. Он содержит только базовые слои (вода, дороги, здания, парки,
подписи) и **не является** финальным: палитра, шрифты, набор подписей и
приоритеты слоёв будут меняться дизайнером.

#### Как менять стиль и оформление города

Стиль — это обычный JSON по [спецификации MapLibre](https://maplibre.org/maplibre-style-spec/),
поэтому менять оформление можно без пересборки архива: достаточно править
`web/map/style.json` и обновлять страницу. Архив содержит **данные**, стиль —
**их отрисовку**, и они независимы.

Что можно настроить:

- **Цвета и толщины** — в `paint` каждого слоя (`fill-color`, `line-width`,
  `line-color`). Например, чтобы выделить центр города, правьте слой
  `landuse-residential` или `building`.
- **Видимость по зуму** — `minzoom`/`maxzoom` слоя. Это не то же самое, что
  зум в архиве: если данных для z16 в архиве нет, слой не появится, сколько бы
  вы ни поставили `minzoom`.
- **Порядок отрисовки** — порядок объектов в массиве `layers`: последний рисуется
  сверху (здания поверх дорог или наоборот).
- **Фильтры** — `filter` по атрибутам тайлов (`class`, `subclass`,
  `hiking_route` и т.д.). Полный список атрибутов по слоям смотрите в метаданных
  архива:
  ```bash
  docker run --rm -v "$PWD/web/static/pmtiles:/out" ghcr.io/protomaps/go-pmtiles:latest \
    show /out/primorsky-krai-z15.pmtiles --metadata
  ```
- **Подписи** — `text-field`, `text-font`, `text-size`, `text-halo-*` в слоях
  типа `symbol`. Шрифты ограничены теми, что лежат в `web/map/fonts/`:
  `Noto Sans Regular`, `Bold`, `Italic`.

Чего стиль **не** может — добавить данные, которых нет в архиве: POI, маркеры
мест из PostGIS, маршруты. Они подключаются отдельными source поверх подложки,
когда появится реальный React-island.

Стили для города и для природы удобно держать как два файла
(`style.city.json`, `style.nature.json`) и переключать `style:` у карты —
архив при этом один и тот же.

### 3. Вендоренные ассеты `web/map/vendor/` и `web/map/fonts/`

MapLibre GL JS (5.24.1), PMTiles (4.5.0) и глифы Noto Sans скачаны вручную и
лежат в репозитории, потому что в проекте пока нет сборщика фронтенда
(`package.json` / Vite / pnpm отсутствуют). Это временное решение:

- версии зафиксированы руками и не обновляются автоматически;
- глифы скопированы только для пяти диапазонов (латиница и кириллица);
- при появлении Vite эти зависимости переедут в `package.json`, а шрифты —
  в пайплайн сборки статики.

Сами по себе локальные ассеты — осознанное требование (карта не должна зависеть
от CDN), но способ их поставки временный.

### 4. `cmd/mapserver`

Отдельный сервер, который поднимает только `/map/` и архив, без Postgres и
остального бекенда. Нужен ровно для того, чтобы разрабатывать карту и бекенд
независимо. В продакшене карта раздаётся основным сервером
(`cmd/server`, маршруты уже зарегистрированы в `routes.NewHTTPRouter`),
а `cmd/mapserver` остаётся локальным инструментом.

### 5. Алиас `/api/pmtiles/region.pmtiles`

Продублирован ради обратной совместимости со старой заглушкой в
`web/static/index.html`, где был прописан именно этот путь. Канонический
адрес — `/api/map/region.pmtiles`; алиас можно удалить вместе с заменой
заглушки на реальный компонент карты. Зарегистрирован только в основном
сервере (`cmd/server`), в `cmd/mapserver` его нет.

### 6. Кнопка «Скачать карту» и Service Worker

Это два демонстрационных механизма, которые вместе дают полноценный офлайн.

**`web/map/offline.js` + кнопка в правом нижнем углу.** По умолчанию тайлы
читаются по HTTP Range, то есть карта работает только при живом бекенде. Кнопка
скачивает весь архив (~90 МБ) в IndexedDB и перезапускает страницу — при старте
источник выбирается **до** создания карты: если копия есть, MapLibre сразу
поднимается на локальном Blob и вообще не обращается к сети. На панели виден
прогресс, размер копии и дата сохранения; кнопка «Удалить копию» возвращает
режим сети.

Источник выбирается на старте намеренно. Попытка подменить его на живой карте
(`setStyle(getStyle())`) ломается при холодной загрузке: `getStyle()` возвращает
`undefined`, пока стиль не загрузился, а `setStyle(undefined)` уничтожает карту —
пропадают слои и источник. Теперь этого окна нет.

**`web/map/sw.js`** кеширует оболочку (страницу, стиль, библиотеки и глифы,
~2.6 МБ), чтобы по F5 без сети открывалась сама страница. Регистрируется
автоматически при загрузке `/map/`.

Для HTML и JS используется **network-first**, а не cache-first. Это принципиально:
cache-first навсегда залипает на старой версии страницы, и исправления не доезжают
до пользователя — именно так один раз уже «залипло» исправление выбора источника
карты. Глифы остаются cache-first: они неизменяемы. Архив он **не**
дублирует — 90 МБ лежат в IndexedDB в единственном экземпляре.

Разделение сделано намеренно:

| Что | Где | Размер |
| --- | --- | --- |
| Оболочка + глифы | Cache Storage (SW) | ~2.6 МБ |
| Просмотренные куски архива | IndexedDB, стор `chunks` | ~150 КБ на экран |
| Архив карты целиком | IndexedDB, стор `archives` | ~90 МБ |

**Куски архива — почему они кешируются отдельно.** Тайлы читаются HTTP
Range-запросами, а ответы `206 Partial Content` браузеры кешируют ненадёжно
(а часто не кешируют вовсе). Поэтому «посмотрел онлайн» само по себе не давало
офлайна: после перезагрузки карта оставалась пустой. Теперь сетевой источник
обёрнут в `cachingSource` из `offline.js`: каждый полученный диапазон
складывается в IndexedDB, и при следующем открытии отдаётся с диска. Проверено
с выключенным HTTP-кешем и остановленным сервером — карта рисуется из IndexedDB.

Почему это временно:

- нет версионирования архива — при пересборке карты старую копию надо удалять
  вручную (кнопкой), автоматической инвалидации нет;
- нет докачки и контроля квоты: если браузеру не хватит места, скачивание
  просто упадёт с ошибкой;
- `navigator.storage.estimate()` в Chrome не учитывает Blob в IndexedDB,
  поэтому «занято» показывать нельзя — выводится только доступная квота;
- SW написан руками; в проде ожидается Workbox из общей офлайн-стратегии
  проекта с нормальными стратегиями и обновлением при деплое.

### 7. Логика hiking-отношений в `process.lua`

В профиле есть обработка отношений `route=hiking`: `relation_scan_function`
принимает такие отношения, `way_function` помечает их участки атрибутом
`hiking_route=1` и опускает их до z12. На момент
сборки (ноябрь 2026) в экстракте Приморского края таких отношений **нет** —
есть только `bus`, `road`, `train`, `ferry`. Поэтому фактически тропы
определяются по тегу `highway` (`path`, `bridleway`), а код для отношений
пока не срабатывает. Он оставлен как задел и заработает, когда отношения
появятся в OSM; до этого его можно считать непроверенным в бою.

## Что покрыто

| Параметр | Значение |
| --- | --- |
| Границы | административная граница Приморского края (OSM relation `151225`, ISO `RU-PRI`) |
| Extent | `130.39, 42.12 – 139.31, 48.47` |
| Zoom | `0–15` (детализация до отдельных зданий и троп) |
| Размер архива | ~96 MB (`z15`, ~427 тыс. тайлов) |
| Формат | MVT (protobuf) внутри PMTiles v3, gzip |
| Слои | `water`, `waterway`, `transportation`, `transportation_name`, `building`, `landuse`, `landcover`, `park`, `poi`, `place`, `boundary`, `mountain_peak`, `aeroway`, `housenumber` |

В покрытие входят Владивосток (агломерация, о. Русский, бухта Петра Великого),
Находка, Уссурийск, побережье Японского моря и частично Сихотэ-Алинь.

Обрезка идёт по административной границе, а не по прямоугольнику: иначе в архив
попадают Китай, Хабаровский край и ЕАО. Пограничные тайлы могут захватывать
соседнюю территорию — это неизбежно при тайловой сетке, таких тайлов менее 2%.

## Быстрый старт

```bash
mise run bootstrap        # .env и зависимости Go
mise run map-download     # скачать OSM и собрать архив (~5–10 мин при первом запуске)
mise run map-serve        # карта на http://127.0.0.1:8080/map/
```

Проверка, что архив отдаётся диапазонами (а не целиком):

```bash
mise run map-check
curl -r 0-1023 http://localhost:8080/api/map/region.pmtiles | head -c 100 | xxd
```

Ожидаемый ответ — `206 Partial Content`, ровно 1024 байта и сигнатура `PMTiles`
в первых байтах.

## Как перегенерировать карту

Полная сборка одной командой:

```bash
mise run map-download
```

Скрипт `scripts/map/build-map.sh` выполняет шаги:

1. **Скачивание** — `far-eastern-fed-district-latest.osm.pbf` (~400 MB) с Geofabrik
   в `.cache/map/`. Файл кэшируется: повторный запуск его не качает.
2. **Граница края** — из экстракта достаётся relation `151225` («Приморский край»,
   `admin_level=4`) и конвертируется в GeoJSON.
3. **Кроп по границе** — `osmium extract --polygon boundary-r151225.geojson` →
   `primorsky.osm.pbf` (~49 MB).
4. **Береговая линия** — Water polygons с osmdata.openstreetmap.de обрезаются
   по той же границе края через GDAL (слой `ocean`). Кэшируется в
   `.cache/map/coastline/`.
5. **Рендер тайлов** — tilemaker с профилем `scripts/map/{config,process}.lua`.
6. **Конвертация** — MBTiles → PMTiles и проверка структуры (`pmtiles verify`).

Параметры переопределяются переменными окружения:

```bash
MAP_MAXZOOM=13 mise run map-download          # более грубая карта, меньше файл
MAP_OUTPUT=/srv/maps/region.pmtiles mise run map-download
MAP_KRAI_RELATION_ID=1647394 mise run map-download   # границы Владивостокского округа
```

Промежуточные файлы складываются в `.cache/map/` (в `.gitignore`), поэтому
повторная сборка после правки профиля занимает секунды.

## Состав пайплайна

```
scripts/map/
├── build-map.sh        # оркестратор: скачивание → граница → кроп → тайлы → PMTiles
├── config.json         # слои, zoom-диапазоны, метаданные архива
├── process.lua         # OpenMapTiles-профиль + правки под хайкинг
└── Dockerfile.tools    # образ tilemaker + osmium (собирается автоматически)
```

Нужен только **Docker**: образы `ghcr.io/systemed/tilemaker`, `ghcr.io/osgeo/gdal`,
`ghcr.io/protomaps/go-pmtiles` подтягиваются автоматически.

## Профиль тайлов

`process.lua` — профиль OpenMapTiles из tilemaker с правками:

- `highway=path` и `highway=bridleway` поднимаются с z14 до **z12**, чтобы тропы
  были видны при планировании маршрута, а не только на максимальном приближении
  (городские тротуары `footway`/`steps`/`pedestrian` остаются на z14: их
  миллионы, и подъём раздул бы архив без пользы для хайкинга);
- у таких линий появляется атрибут `hiking_route=1`.

Верхний зум детализации вынесен в константу `MAX_ZOOM` в самом профиле и должен
совпадать с `maxzoom`/`basezoom` в `config.json`. Профиль не читает конфиг, поэтому
при смене зума правятся оба места — `build-map.sh` подставляет `MAP_MAXZOOM`
в конфиг автоматически, но `process.lua` при нестандартном значении нужно
поправить руками.

## Эндпоинты

| Метод | Путь | Статус |
| --- | --- | --- |
| `GET`/`HEAD` | `/api/map/region.pmtiles` | постоянный, поддерживает `Range` |
| `GET`/`HEAD` | `/api/pmtiles/region.pmtiles` | демонстрационный алиас, только в `cmd/server` |
| `GET` | `/map/` | демонстрационная страница |
| `GET` | `/map/**` | ассеты демонстрационной страницы |

Алиас `/api/pmtiles/region.pmtiles` зарегистрирован только в основном сервере
(`routes.NewHTTPRouter`); в `cmd/mapserver` его нет — демо-страница использует
канонический `/api/map/region.pmtiles`.

Архив отдаётся с `Accept-Ranges: bytes` и `Cache-Control: public, max-age=3600`.
Если файла нет, эндпоинт отвечает `503` с подсказкой запустить
`mise run map-download`, а демо-страница показывает инструкцию вместо пустого
экрана.

## Разработка карты отдельно от бекенда

`cmd/mapserver` поднимает только карту и архив — без Postgres и остальных сервисов:

```bash
mise run map-serve          # http://127.0.0.1:8080/map/
```

Флаги: `-addr :8080`, `-map-dir ./web/map`,
`-archive ./web/static/pmtiles/primorsky-krai-z15.pmtiles`,
`-relief ./web/static/pmtiles/primorsky-relief.pmtiles`
(или переменные `MAP_ADDR`, `MAP_DIR`, `PMTILES_PATH`, `RELIEF_PATH`).

Оба режима отдаются одним сервером: если архив рельефа собран, эндпоинт
`/api/map/relief.pmtiles` поднимается автоматически и на странице работает
переключатель «Город/Природа». Без архива стиль вырезает растровый слой,
а кнопка «Природа» выключена — флаги режимов не нужны.

## Известные ограничения

- **Офлайн работает только после явного скачивания.** Пока кнопка «Скачать
  карту» не нажата, архив читается по `Range` и без сети не отрисуется. После
  скачивания карта работает офлайн полностью, включая перезагрузку по `F5`
  (оболочку отдаёт Service Worker) и повторный запуск браузера.
- **Кеш кусков неполный.** После онлайн-просмотра офлайн доступны только те
  области (и только те тайлы), которые реально запрашивались. Если поехать
  в неисследованный район без сети, там карта будет пустой. Полный офлайн даёт
  только кнопка «Скачать карту».
- **Кеш кусков не чистится автоматически.** Он растёт по мере просмотра. При
  пересборке архива старые куски устаревают: их нужно сбросить вместе с копией
  (кнопкой «Удалить копию»).
- **Пустая карта теперь диагностируется.** Если тайлы не пришли (нет сети и нет
  копии), страница показывает «Тайлы не загрузились» с объяснением, а не молчит.
- **Нет автообновления офлайн-копии.** После пересборки архива старую копию
  нужно удалить кнопкой и скачать заново.
- **Нет слоя приложения.** Демо-страница показывает только подложку; маркеры,
  кластеры и маршруты из PostGIS не подключены.
- **Стиль не финальный** — см. раздел про временные компоненты.

## Если архив больше 500 MB

Текущая сборка — ~96 MB, запас большой. Если после смены зума файл перевалит
за 500 MB, скрипт сам выведет предупреждение. Варианты:

1. **Снизить максимальный зум** — самый эффективный рычаг:
   ```bash
   MAP_MAXZOOM=13 mise run map-download
   ```
2. **Два архива (LOD-схема)** — z13 на весь край + z15 на агломерацию:
   ```bash
   MAP_MAXZOOM=13 MAP_OUTPUT=web/static/pmtiles/primorsky-z13.pmtiles mise run map-download
   MAP_MAXZOOM=15 MAP_OUTPUT=web/static/pmtiles/vladivostok-z15.pmtiles mise run map-download
   ```
   Для второго архива область задаётся OSM-отношением через `MAP_KRAI_RELATION_ID`
   (например, `1647394` — Владивостокский городской округ), а не прямоугольником.
   На фронте детальный архив подключается как дополнительный source и включается
   при `zoom >= 13`.
3. **zstd** — PMTiles уже хранит тайлы gzip-сжатыми, поэтому повторное сжатие
   архива даёт единицы процентов. Реальный выигрыш даёт только снижение зума
   или отказ от слоя `building` на больших зумах.

## Проверка результата

- **Range-запросы**: `mise run map-check` (ожидает `206` и 1024 байта).
- **Валидность архива**: `pmtiles verify` вызывается скриптом сборки автоматически;
  визуально архив открывается на <https://pmtiles.io/>.
- **Офлайн-режим**: в devtools включить Offline и подвигать карту — тайлы уже
  открытого архива продолжают рисоваться (проверено: 1055 объектов при
  отключённой сети).
- **Размер**: `mise run map-size` — должно быть меньше 500 MB.
