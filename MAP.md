# Офлайн-карта Приморского края

Карта региона собирается в PMTiles-архивы и раздаётся бекендом байтовыми
диапазонами. В git архивы не попадают (десятки и сотни MB): файлы лежат на
диске сервера, локально собираются командами из `mise.toml`.

## Компоненты

| Компонент | Назначение |
| --- | --- |
| `scripts/map/build-map.sh`, `config.json`, `process.lua` | Сборка векторного архива из OSM |
| `scripts/map/build-relief.sh`, `scripts/map/relief/` | Сборка из Copernicus DEM GLO-30: зоны высот с отмывкой (`primorsky-relief.pmtiles`), векторные горизонтали (`primorsky-contours.pmtiles`), DEM в terrarium-RGB (`primorsky-dem.pmtiles`, приложение его не использует). Шаги — в [web/map/PIPELINE.md](web/map/PIPELINE.md) |
| `scripts/map/water/10-water-tiles.sh` | Мировая вода из Natural Earth (`primorsky-water.pmtiles`) |
| `web/static/pmtiles/*.pmtiles` | Артефакты сборки, в git не коммитятся |
| `internal/application/routes/http/pmtiles.go` | Отдача архивов с `Range` и `ETag` |
| `internal/application/routes/http/map_page.go` | Стиль (вырезает источники отсутствующих архивов), ассеты `/map/*` без листинга каталогов |
| `web/map/style.json` | Стиль подложки: слои, режимы, ссылки на токены |
| `web/map/vendor/`, `web/map/fonts/` | MapLibre GL JS 5.24.1, PMTiles 4.5.0, глифы Noto Sans: карта не зависит от CDN |
| `web/static/js/app/map.js` | Контроллер карты приложения: маркеры, кластеры, маршрут, мини-карты |
| `web/static/js/app/map-style.js` | Загрузка стиля, подстановка токенов, режимы слоёв |
| `web/static/js/app/map-tiles.js` | Протокол `pmtiles://`, кеш кусков, скачанная копия |
| `web/static/js/app/offline-map.js` | Блок «Офлайн-карта» в профиле |
| `cmd/mapserver` (+ вшитая `dev.html`) | Отладка стиля без Postgres |

Карта используется на «Карте», в «Сейчас», в мини-карте страницы места и при
выборе точки в мастере добавления. Везде она создаётся через `createPlacesMap`
или `createBaseMap` из `map.js`, поэтому подложка, стиль и офлайн у них общие.

## Стиль и токены

Цвета в `web/map/style.json` записаны ссылками на CSS-токены:
`"fill-color": "var(--map-park)"`. Значения токенов лежат в
`web/static/css/app.css` (блок «Карта» в `:root`), `map-style.js` подставляет
их перед созданием карты. Так карта и интерфейс меняют цвета в одном месте:
новый цвет в стиле — это новый токен `--map-*` в `app.css`. Неизвестный токен
выводит предупреждение в консоль и рисуется чёрным.

MapLibre, открытый напрямую на `style.json`, ссылки `var(...)` не поймёт,
поэтому стиль смотрят и правят на отладочной странице `mise run map-serve` →
`/map/`. Она рисует карту тем же модулем, что и приложение, и подхватывает
правки `style.json` и `app.css` по F5 без сборки.

Что можно настроить:

- Цвета и толщины — в `paint` слоя (`line-width`, `fill-color`) или в токене.
  Ширины дорог интерполируются экспоненциально до z18: архив заканчивается на
  z15, дальше MapLibre масштабирует тайлы сам.
- Видимость по зуму — `minzoom`/`maxzoom` слоя. Данных выше зума архива не
  появится, какой бы `minzoom` ни стоял.
- Порядок отрисовки — порядок в массиве `layers`: последний рисуется сверху.
  Обводки дорог (`*-casing`) стоят под всеми заливками, иначе рвутся перекрёстки.
- Фильтры — по атрибутам тайлов (`class`, `subclass`, `hiking_route`,
  `admin_level`). Полный список атрибутов — в метаданных архива:
  ```bash
  docker run --rm -v "$PWD/web/static/pmtiles:/out" ghcr.io/protomaps/go-pmtiles:latest \
    show /out/primorsky-krai-z15.pmtiles --metadata
  ```
- Подписи — `text-field`, `text-font`, `text-size`, `text-halo-*`. Доступны
  только шрифты из `web/map/fonts/`: `Noto Sans Regular`, `Bold`, `Italic`,
  латиница и кириллица.

Решения из дизайна (`vlru-places/docs/map.md`): POI-подписи выключены,
смысловые точки ставит только продукт. Границы рисуются только крупные
(`admin_level <= 4`): муниципальные идут по берегу и сливаются с ним в
пунктир. Морские участки границ отбрасываются ещё при сборке тайлов.

## Режимы «Город» и «Природа»

Режим слоя задан в `metadata["hermes:mode"]`: `city`, `nature` или `both`
(слой без метки считается `city`). «Город», «Море» и «Сейчас» включают режим
`city`, «Природа» — `nature`. Режим выбирается до создания карты, поэтому
лишние слои не мелькают.

В режиме `nature` карта показывает растровый рельеф (`relief-zones`),
векторные горизонтали (`contours-*`), воду, полупрозрачный лес
(`landcover-wood-nature`), тропы и вершины с именем и отметкой высоты.
Участки маршрутов (`hiking_route=1`) рисуются сплошной зелёной линией с тёмной
обводкой, остальные тропы — приглушённым пунктиром.

Рельеф плоский: объём даёт отмывка, запечённая в растр при сборке (цвет ×
hillshade). 3D-terrain не используется: один PNG на тайл грузится быстро, а
без наклона камеры маркеры и панели не съезжают. Образец вида — туристический
слой mapy.com и OpenTopoMap: фон — плавный зелёный градиент высот, форму
склонов дают отмывка и плотные кольца горизонталей.

Горизонтали в растр не запекаются. Они лежат отдельным векторным архивом
`primorsky-contours.pmtiles` (MVT z5–14, поля `ELEV` и `kind`), и MapLibre
рисует их линиями: при оверзуме линии остаются чёткими, а цвет и толщина
меняются правкой стиля без пересборки. Слои — `contours-minor` (каждые 20 м
с z12) и `contours-major` (каждые 100 м с z8).

Пайплайн рельефа (Copernicus DEM GLO-30, ~30 м/px), подробно — в
[PIPELINE.md](web/map/PIPELINE.md):

1. DEM сглаживается сепарабельным гауссианом (`relief/20-smooth.py`). Сырой
   GLO-30 шумит (артефакты интерферометрии), и отмывка из него выходит
   «шубой». Размытие сохраняет форму склонов, так же делает OpenTopoMap.
2. Горизонтали строятся `gdal_contour` (атрибут `ELEV`) из сглаженного DEM:
   мелкие каждые 20 м, крупные каждые 100 м. Дальше — сглаживание Чайкином
   (2 итерации), GeoJSON и MVT через ogr2ogr: на z5–11 только крупные
   (`kind=major`), на z12–14 все. В архив пишется `tilejson` с
   `vector_layers`: без него pmtiles-протокол MapLibre не поднимет источник.
3. Отмывка и цвет считаются на сетке x2 (~15 м/px, cubic-апсемпл), чтобы линии
   оставались тонкими в тайлах z15 (~4.8 м/px). Масштаб градус→метры —
   `-s 111120`: с `-s 1` на географическом растре склоны занижены в ~111 000
   раз и рельеф выходит плоским. z-фактор 2. Палитра — `relief/zones.py`.
4. Цвет смешивается с отмывкой полосами по 2048 строк (`relief/70-blend.py`)
   и обрезается по контуру суши края (`-cutline -dstalpha`), поэтому охват
   «Природы» совпадает с городской картой. Нарезка — gdalwarp + gdal2tiles,
   ресемплинг cubic на обеих ступенях, на клиенте `raster-resampling: linear`.
   Nearest на любой ступени возвращает «пиксели», не включайте его обратно.

Яркость и насыщенность растра подстраиваются полями `raster-*` слоя, а
горизонталей — `paint` слоёв `contours-*`, без пересборки. DEM-архив скрипт
собирает, но приложение его не использует; при правке только палитры или
горизонталей его можно пропустить (`RELIEF_SKIP_DEM=1`).

Диапазон зумов рельефа берётся из заголовка архива, а не из стиля: локальная
сборка (`map-relief-local`) покрывает z10–13, полная — z3–15. Размер архива
сознательно не ограничен (сетка x2 и z15 дают сотни тысяч тайлов), поэтому
целиком на клиента он не скачивается: тайлы отдаются по HTTP Range, в
IndexedDB попадают только просмотренные куски. Ниже покрытия под рельефом
виден фон `--map-nature-land` (цвет суши) с водой и подписями.

Если архива рельефа или горизонталей на сервере нет, `MapStyleHandler`
вырезает источник и его слои, а «Природа» показывает городскую подложку.
Наличие архива проверяется на каждый запрос стиля, так что после сборки
перезапускать сервер не нужно.

## Офлайн

Порядок источников для каждого куска архива (`map-tiles.js`):

1. Сервер, HTTP `Range`. Основной путь, всегда первый.
2. Скачанная копия, если сеть или сервер недоступны и копия есть.
3. Кеш кусков: всё, что карта уже получала онлайн.

| Что | Где | Размер |
| --- | --- | --- |
| Просмотренные куски архивов | IndexedDB `hermes-map`, стор `chunks` | ~150 КБ на экран |
| Скачанные архивы целиком | IndexedDB `hermes-map`, стор `archives` | карта ~96 МБ + рельеф и горизонтали (сотни МБ) |

**Кеш кусков.** Ответы `206 Partial Content` браузеры кешируют ненадёжно,
поэтому каждый полученный диапазон складывается в IndexedDB пачками раз в
300 мс. Уже просмотренные области потом открываются без сервера.

**Скачанная копия.** Блок «Офлайн-карта» в профиле (только после входа)
скачивает все собранные архивы целиком, показывает прогресс, размер и дату,
умеет отменять, удалять копию и очищать кеш кусков. Копия хранится на
устройстве и к аккаунту не привязана. После скачивания запрашивается
`navigator.storage.persist()`, чтобы браузер не вытеснил данные.

**Версии.** `PMTilesHandler` отдаёт сильный `ETag` из размера и mtime файла
(`http.ServeFile` его сам не ставит). Куски кешируются с ключом
`<архив>|<ETag>|<смещение>:<длина>`; когда приходит кусок с новым ETag, старые
куски этого архива удаляются. Копия хранит свой ETag, и офлайн-сессия, начатая
с копии, читает только её версию: смещения старого и нового архива указывают
в разные байты, смешивать их нельзя. Профиль сравнивает ETag копии с сервером
и предлагает «Обновить», когда архив пересобран.

## Hiking-отношения в `process.lua`

`relation_scan_function` принимает отношения `route=hiking`, а `way_function`
помечает их участки атрибутом `hiking_route=1` и показывает с z12. В экстракте
Приморского края на ноябрь 2026 таких отношений нет, есть только `bus`, `road`,
`train` и `ferry`. Поэтому тропы определяются по тегу `highway` (`path`,
`bridleway`), а код для отношений не срабатывает и в бою не проверен. Он
заработает, когда отношения появятся в OSM.

## Что покрыто

| Параметр | Значение |
| --- | --- |
| Границы | административная граница Приморского края (OSM relation `151225`, ISO `RU-PRI`) |
| Extent | `130.39, 42.12 – 139.31, 48.47` |
| Zoom | `0–15` (детализация до отдельных зданий и троп) |
| Размер архива | ~96 MB (`z15`, ~427 тыс. тайлов) |
| Формат | MVT (protobuf) внутри PMTiles v3, gzip |
| Горизонтали | отдельный архив `primorsky-contours.pmtiles`, слой `contours`, поля `ELEV` (высота, м) и `kind` (`major` — каждые 100 м, `minor` — каждые 20 м), z5–14 |
| Слои | `water`, `waterway`, `transportation`, `transportation_name`, `building`, `landuse`, `landcover`, `park`, `poi`, `place`, `boundary`, `mountain_peak`, `aeroway`, `housenumber` |

В покрытие входят Владивосток (агломерация, о. Русский, бухта Петра Великого),
Находка, Уссурийск, побережье Японского моря и часть Сихотэ-Алиня.

Обрезка идёт по административной границе, а не по прямоугольнику, иначе в
архив попадают Китай, Хабаровский край и ЕАО. Пограничные тайлы могут
захватывать соседнюю территорию, это неизбежно при тайловой сетке; таких
тайлов меньше 2%.

## Сборка

```bash
mise run map-ensure        # собрать все недостающие архивы
mise run map-download      # векторная карта (~5–10 мин при первом запуске)
mise run map-relief        # рельеф, горизонтали, DEM (~2 ч)
mise run map-relief-local  # рельеф только агломерации, быстро
mise run map-water         # мировая вода (шейпы Natural Earth — вручную, см. PIPELINE.md)
mise run map-size          # размеры собранных архивов
```

`mise run build city-map` и `mise run build relief-map` делают то же, что
`map-download` и `map-relief`, но скачивание исходников вынесено в отдельные
таски `fetch:*`.

`scripts/map/build-map.sh` собирает векторный архив так:

1. Скачивает `far-eastern-fed-district-latest.osm.pbf` (~400 MB) с Geofabrik
   в `.cache/map/`. Повторный запуск файл не качает.
2. Достаёт из экстракта relation `151225` («Приморский край»,
   `admin_level=4`) и конвертирует в GeoJSON.
3. Обрезает экстракт по границе: `osmium extract --polygon boundary-r151225.geojson` →
   `primorsky.osm.pbf` (~49 MB).
4. Обрезает water polygons с osmdata.openstreetmap.de по той же границе через
   GDAL (слой `ocean`). Результат кешируется в `.cache/map/coastline/`.
5. Рендерит тайлы tilemaker'ом с профилем `scripts/map/process.lua` и
   конфигом `scripts/map/config.json`.
6. Конвертирует MBTiles в PMTiles и проверяет структуру (`pmtiles verify`).

Нужен только Docker: образы `ghcr.io/systemed/tilemaker`, `ghcr.io/osgeo/gdal`
и `ghcr.io/protomaps/go-pmtiles` подтягиваются автоматически, tilemaker с
osmium собирается из `scripts/map/Dockerfile.tools`.

Параметры переопределяются переменными окружения:

```bash
MAP_MAXZOOM=13 mise run map-download          # более грубая карта, меньше файл
MAP_OUTPUT=/srv/maps/region.pmtiles mise run map-download
MAP_KRAI_RELATION_ID=1647394 mise run map-download   # границы Владивостокского округа
```

Промежуточные файлы складываются в `.cache/map/` (в `.gitignore`), поэтому
повторная сборка после правки профиля занимает секунды.

Проверка:

```bash
curl -s -o /dev/null -w '%{http_code} %{size_download}\n' \
  -r 0-1023 http://localhost:8080/api/map/region.pmtiles   # 206 1024
mise run map-size                                          # карта меньше 500 MB
```

`pmtiles verify` вызывается скриптом сборки; визуально архив можно открыть на
<https://pmtiles.io/>. Офлайн-режим проверяется так: на открытой карте
заблокировать в devtools запросы `*.pmtiles` и подвигать карту. Просмотренные
области рисуются из кеша кусков, остальные — из скачанной в профиле копии.

## Профиль тайлов

`process.lua` — профиль OpenMapTiles из tilemaker с правками:

- `highway=path` и `highway=bridleway` показываются с z12 вместо z14, чтобы
  тропы были видны при планировании маршрута. Городские `footway`, `steps` и
  `pedestrian` остаются на z14: их миллионы, и они раздули бы архив без
  пользы для хайкинга;
- у таких линий появляется атрибут `hiking_route=1`.

Верхний зум задан константой `MAX_ZOOM` в профиле и должен совпадать с
`maxzoom`/`basezoom` в `config.json`. Профиль конфиг не читает: `build-map.sh`
подставляет `MAP_MAXZOOM` в конфиг автоматически, а `process.lua` при
нестандартном значении правится руками.

## Эндпоинты

| Метод | Путь | Что |
| --- | --- | --- |
| `GET`/`HEAD` | `/api/map/region.pmtiles` | векторный архив, `Range` + `ETag` |
| `GET`/`HEAD` | `/api/map/relief.pmtiles` | архив рельефа (зоны + отмывка), `Range` + `ETag` |
| `GET`/`HEAD` | `/api/map/contours.pmtiles` | векторные горизонтали, `Range` + `ETag` |
| `GET`/`HEAD` | `/api/map/water.pmtiles` | мировая вода, `Range` + `ETag` |
| `GET` | `/map/style.json` | стиль без источников несобранных архивов |
| `GET` | `/map/**` | MapLibre, PMTiles, глифы |
| `GET` | `/map/` | отладочная страница, только в `cmd/mapserver` |

Архивы отдаются с `Accept-Ranges: bytes` и `Cache-Control: public, max-age=3600`.
Если файла нет, эндпоинт отвечает `503`, и карта в приложении показывает
«Карта не загрузилась».

## Разработка карты отдельно от бекенда

`cmd/mapserver` поднимает стиль, архивы, статику приложения и отладочную
страницу без Postgres и остальных сервисов:

```bash
mise run map-serve          # http://127.0.0.1:8080/map/ (?s=nature — сразу «Природа»)
```

Флаги: `-addr :8080`, `-map-dir ./web/map`, `-web-dir ./web/static`,
`-archive ./web/static/pmtiles/primorsky-krai-z15.pmtiles`,
`-relief ./web/static/pmtiles/primorsky-relief.pmtiles`,
`-contours ./web/static/pmtiles/primorsky-contours.pmtiles`,
`-water ./web/static/pmtiles/primorsky-water.pmtiles`
(или переменные `MAP_ADDR`, `MAP_DIR`, `WEB_DIR`, `PMTILES_PATH`,
`RELIEF_PATH`, `CONTOURS_PATH`, `WATER_PATH`).

Страница грузит модули `web/static/js/app/` и `app.css` напрямую, без бандла,
поэтому правки JS, CSS и стиля видны по F5. В приложение JS попадает только
через `mise run assets`.

## Известные ограничения

Баги отрисовки — в [TODO.md](TODO.md#карта).

- **Без сети не открывается сама страница.** Service Worker для оболочки
  приложения нет, поэтому офлайн-копия и кеш кусков помогают, только когда
  страница уже открыта или недоступен один сервер карты. Полный офлайн требует
  precache оболочки, см. «Офлайн-стратегию» в README.
- **Кеш кусков неполный.** Без сети и без скачанной копии доступны только те
  области и зумы, которые реально запрашивались.
- **Кеш кусков не ограничен по размеру.** Он растёт по мере просмотра, очистить
  его можно в профиле. Старая версия вытесняется автоматически при пересборке
  архива.
- **Скачивание не докачивается.** При обрыве или нехватке места скачивание
  начинается заново; прежняя копия остаётся, пока новая не скачана целиком.
- **Скачивание держит архивы в памяти** до записи в IndexedDB.

## Если архив больше 500 MB

Текущая сборка весит ~96 MB. Если после смены зума файл перевалит за 500 MB,
скрипт выведет предупреждение. Варианты:

1. Снизить максимальный зум, это самый действенный рычаг:
   ```bash
   MAP_MAXZOOM=13 mise run map-download
   ```
2. Два архива (LOD-схема): z13 на весь край и z15 на агломерацию:
   ```bash
   MAP_MAXZOOM=13 MAP_OUTPUT=web/static/pmtiles/primorsky-z13.pmtiles mise run map-download
   MAP_MAXZOOM=15 MAP_OUTPUT=web/static/pmtiles/vladivostok-z15.pmtiles mise run map-download
   ```
   Для второго архива область задаётся OSM-отношением через `MAP_KRAI_RELATION_ID`
   (например, `1647394` — Владивостокский городской округ). На фронте
   детальный архив подключается как дополнительный source и включается при
   `zoom >= 13`.
3. zstd почти ничего не даст: PMTiles уже хранит тайлы gzip-сжатыми, повторное
   сжатие экономит единицы процентов. Реально уменьшают архив только снижение
   зума или отказ от слоя `building` на больших зумах.
